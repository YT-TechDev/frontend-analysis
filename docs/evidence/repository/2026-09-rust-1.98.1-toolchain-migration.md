# Rust 1.98.1 Toolchain Migration Checkpoint (2026-09)

## Classification and authority

This is a durable repository/toolchain qualification record, not normative
architecture, toolchain policy, or language-semantic authority. ADR 0002 and
Issue #42 own the exact-pin policy; Issue #42 comment 5749824020 owns the
focused migration research and falsification envelope; Issue #782 owns this
executable migration.

Official Rust 1.98.1 release evidence identified by the focused migration
research was reviewed before implementation. The locally resolved candidate
also reported `rustc 1.98.1 (48a229cea 2026-09-01)` and
`cargo 1.98.1 (797e8a9bc 2026-08-05)` before repository authority changed.

## Baseline and decision

The refrozen pre-migration baseline was commit
`cbbfa2a6fcf557d784403cad31b3487612439388`, tree
`f9c6061881382805355cc4a77392227d5aee1411`. Exact stable Rust 1.97.1 remained
repository authority and passed the workspace validator, formatting, Clippy,
all 4,558 tests, and locked offline metadata validation.

The migration changes the accepted exact stable pin from 1.97.1 to 1.98.1.
Floating `stable` remains rejected; Edition 2024 and resolver 3 remain
unchanged; no `rust-version` or MSRV promise is introduced.

## Qualified surfaces

Current-state ownership was updated in `rust-toolchain.toml`, Rust Core CI, the
workspace-policy validator, contributor/current-state documentation, and the
compiler-sealed HTML ownership harness. Historical records that truthfully
report Rust 1.97.1 validation were preserved.

The compiler-dependent harness now requires one concrete resolved stable Rust
1.98.1 executable. Its coherence, privacy, missing-owner, concrete-executable,
fixture-working-directory, wrong-version, channel-suffix, and prefix-collision
falsification pressures remain intact. No HTML production semantics changed.

`Cargo.lock` did not change. Locked metadata continues to report one workspace
member, one package (`frontend-analysis-core` 0.4.0), zero dependencies, and one
library target. Cargo manifests, package identity, workspace topology, Edition
2024, resolver 3, undefined MSRV, target policy, publication policy, public API,
serialization, language semantics, browser/runtime boundaries, async,
concurrency, and unsafe policy remain unchanged. Issue #781 remains separate.
